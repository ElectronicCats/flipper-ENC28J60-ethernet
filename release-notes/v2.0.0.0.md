`#` What's Changed in v2.0.0.0

This release introduces the first public implementation of **Passive Discovery** for the Flipper Ethernet App, expanding its network reconnaissance capabilities with passive Layer 2 discovery through **LLDP** while laying the architectural foundation for future protocols such as **CDP** and **EAPOL**.

The update also delivers a major refactor of the Passive Discovery subsystem, introducing a shared Neighbor Database, a redesigned multi-scene navigation workflow, and significant improvements to application stability, thread lifecycle management, packet capture handling, and overall user experience.

---

# Application Navigation Redesign

This release introduces a complete reorganization of the application's navigation hierarchy.

The previous single main menu has been replaced by a **Category Menu**, separating administrative networking tools from offensive security features to provide a clearer workflow for both network management and penetration testing activities.

## New Menu Organization

The application is now organized into two primary categories:

### Admin

* Get IP
* Scan Hosts
* Passive Discovery
* Ping Host
* Scan Ports
* OS Detector
* Settings
* About Us

### Pentest

* ARP Actions
* Packet Sniffer
* View Packets

This redesign simplifies navigation while providing a scalable foundation for future reconnaissance and offensive networking modules.

# Passive Discovery Framework

One of the primary goals of this release was extending the Flipper Ethernet App beyond active network scanning by introducing passive network reconnaissance capabilities.

The new Passive Discovery framework continuously listens for Layer 2 discovery protocols and organizes discovered devices into a reusable Neighbor Database that can be shared across future passive networking modules.

## LLDP Support

This release introduces the first supported passive discovery protocol:

* IEEE 802.1AB LLDP frame parsing
* TLV decoding
* Chassis ID extraction
* Port ID extraction
* System Name parsing
* Management Address support
* Neighbor identification by MAC address
* Shared Neighbor Database integration

This functionality enables the Flipper Zero to identify nearby managed switches, routers, access points, servers, and other LLDP-enabled devices without transmitting discovery traffic onto the network.

# Neighbor Discovery Workflow

Passive Discovery was redesigned around a dedicated navigation workflow that separates configuration, discovered neighbors, and device details into independent scenes.

## New Passive Discovery Interface

The user interface now includes dedicated scenes for:

* Passive Discovery configuration
* Neighbor List
* Neighbor Details

This redesign significantly simplifies navigation while making the codebase easier to maintain and extend as additional passive protocols are integrated.

---

# Neighbor Database

A new shared Neighbor Database was implemented to centralize information collected from passive discovery protocols.

The database automatically stores discovered devices, merges repeated observations, updates existing entries, and provides a common interface for future protocol implementations.

Several internal improvements were made during development:

* Simplified Neighbor data model
* Improved update and merge logic
* Source-aware neighbor handling
* Removal of obsolete legacy structures
* Improved duplicate detection
* Better runtime stability

---

# Passive Discovery Reliability Improvements

A considerable portion of this release focused on stabilizing the new Passive Discovery infrastructure.

Several lifecycle and synchronization issues discovered during development were resolved, including improvements to:

* Thread lifecycle management
* Scene initialization and cleanup
* GUI synchronization
* Scanner session ownership
* Neighbor update consistency
* Runtime crash prevention
* NULL pointer protection

These changes substantially improve reliability when entering, exiting, and repeatedly using Passive Discovery.

---

# General Stability Improvements

Several improvements were implemented across the application to provide a more consistent experience during everyday use.

Highlights include:

* Fixed return navigation across networking features when no Ethernet connection is available.
* Improved scene transitions.
* Better error handling during unavailable network conditions.
* More robust runtime behavior throughout the application.

The internal architecture now provides a cleaner foundation for implementing additional passive discovery protocols while improving long-term maintainability of the codebase.
