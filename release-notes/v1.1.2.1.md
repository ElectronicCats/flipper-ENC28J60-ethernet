# What's Changed in v1.1.2.1

This release significantly expands the Flipper Ethernet application's network reconnaissance capabilities, introducing entirely new network analysis tools including **OS Detector**, **Port Scanner**, and **Ping**, alongside a major internal networking refactor focused on stability, responsiveness, and long-term maintainability.

The update improves TCP/IP fingerprinting capabilities, adds reusable host-selection workflows across modules, reorganizes the UI around a more natural network-audit flow, and introduces a new shared scanner session architecture used across Ping, ARP scanning, Port Scanning, and OS Detection.

This release also includes major reliability improvements around packet handling, RX dispatching, DHCP/DORA behavior, UI responsiveness, PCAP handling, and long-running capture operations.

---

# New Network Reconnaissance Features

One of the biggest goals of this release was transforming the application from a basic Ethernet utility into a much more capable embedded network reconnaissance toolkit for Flipper Zero.

This version introduces several major networking tools that dramatically expand what can be analyzed directly from the device.

## OS Detector *(Experimental)*

OS Detector is one of the largest additions in this release cycle, introducing active TCP/IP fingerprinting capabilities directly on the Flipper Zero.

The feature is currently marked as **EXPERIMENTAL** while the fingerprinting engine continues evolving and additional validation is performed across more real-world network environments.

The detector combines multiple TCP/IP heuristics to estimate the operating system running on a remote host using low-level packet analysis techniques.

### Fingerprinting capabilities

* Added weighted heuristic scoring using:

  * TTL analysis
  * IPID behavior
  * TCP Window Size analysis

* Added advanced TCP option parsing and validation logic to improve fingerprint reliability.

* Added ICMP probing support as part of the fingerprinting workflow.

* Added TCP probe support and improved scan result reporting.

* Added retry logic and port-state tracking to improve consistency when targets respond intermittently.

* Improved TCP/IP heuristic scoring and OS classification accuracy.

### Reliability improvements

Several fixes and safeguards were added during development:

* Added strict TCP option boundary validation to prevent malformed packets from corrupting fingerprint parsing.
* Fixed RST responses incorrectly appearing as `UNKNOWN` instead of `CLOSED`.
* Added fail-fast handling when ARP resolution fails before scans begin.
* Added clear `EXPERIMENTAL` labeling throughout the UI and result screens.

Despite its current experimental state, the feature already provides a strong foundation for embedded TCP/IP fingerprinting directly from the Flipper platform.

## New Port Scanner

This release also introduces a fully integrated Port Scanner capable of performing TCP SYN-based scanning workflows directly from the Flipper Ethernet application.

The scanner was designed to integrate closely with ARP host discovery and the new OS Detection engine, allowing users to move naturally from host discovery → port enumeration → operating system fingerprinting.

### Port Scanner features

* Added TCP SYN scanning support.
* Added shared scanned-host selection workflows.
* Added reusable ARP-discovered target lists across modules.
* Added proper numerical keyboard handling for port-range configuration.
* Added retry logic and improved scan result consistency.

### Scanner reliability improvements

Several protocol-handling and UI stability fixes were implemented during development:

* Improved SYN/ACK and RST/ACK matching logic.
* Fixed incorrect TCP flag masking behavior.
* Removed unstable early-break logic that caused UI hangs and occasional device reboots during heavy scans.
* Fixed protocol-selection persistence after navigation changes.
* Improved packet filtering consistency during long-running scans.

## New Ping Tool

A dedicated Ping feature was added as part of the new shared networking infrastructure.

While simple on the surface, the implementation required significant backend work to reliably handle ICMP echo traffic within the application's evolving RX dispatch architecture.

### Ping improvements

* Added ICMP Echo Request / Echo Reply handling.
* Added integration with the new shared scanner session infrastructure.
* Improved packet ownership consistency between concurrent RX handlers.
* Fixed cases where valid echo replies were consumed by competing packet-processing paths and incorrectly reported as packet loss.
* Added cancel-aware packet waiting behavior for improved UI responsiveness during long-running operations.

# Hardware Interrupt-Driven Networking Engine

One of the largest internal changes in this release was the migration away from the legacy polling-based receive loop toward a dedicated interrupt-driven RX dispatch architecture.

This redesign improves packet responsiveness, reduces unnecessary SPI activity, and allows multiple networking features to coexist more reliably without competing for packet ownership.

## RX dispatch architecture

The networking backend now uses a centralized RX dispatch system capable of routing packets to registered handlers using predicate-based matching logic.

This allows:

* asynchronous packet processing
* cleaner scanner isolation
* better packet ownership handling
* reduced frame collisions during concurrent operations
* improved UI responsiveness during active networking tasks

## Interrupt-driven packet handling

The ENC28J60 driver was updated to support interrupt-driven packet reception using the module INT pin instead of relying entirely on continuous polling loops.

This significantly reduces idle SPI overhead and improves responsiveness during active network activity.

## Shared scanner session infrastructure

A new shared scanner session layer was introduced and integrated across the application's networking tools.

The new scanner session system centralizes:

* packet waiting
* cancellation handling
* next-hop resolution
* scan lifecycle management
* predicate-based packet matching

through reusable scanner primitives such as:

* `scanner_wait_for_packet`
* `scanner_cancel_requested`
* `scanner_resolve_next_hop`

## Migrated modules

The refactor migrated multiple networking tools onto the shared scanner session layer:

* Ping
* ARP Scan
* TCP SYN Scan
* OS Detector
* ARP Spoofing

This migration introduced several practical improvements:

* cleaner packet matching logic
* reduced duplicated polling loops
* more reliable packet filtering
* improved scan consistency in noisy environments
* cancel-aware scanning across modules
* improved thread coordination between UI and networking tasks

# Networking & DHCP Improvements

Core networking behavior received multiple reliability improvements focused on DHCP handling, gateway persistence, and background protocol processing.

## DHCP/DORA improvements

* Increased DHCP timeout handling for better compatibility with slower production DHCP servers.
* Added cancellable DORA operations to prevent long UI freezes during acquisition.
* Improved persistence of DHCP, gateway, and network state information.
* Fixed incorrect gateway-state handling during DHCP ACK processing.
* Prevented DHCP packets from being consumed by unrelated RX handlers during negotiation.

## Auto-ARP and Auto-ICMP improvements

Automatic ARP replies and ICMP echo responses are now processed through registered RX dispatch handlers instead of independent polling loops.

This improves reliability during concurrent networking operations and reduces packet contention across modules.

# Stability & Reliability Fixes

A large portion of this release focused on improving runtime stability, memory safety, and long-running operation reliability.

## Sniffer improvements

* Fixed BACK button handling during active captures.
* Improved capture exit behavior and scene responsiveness during sniffing sessions.
* Added validation checks when initializing PCAP captures.
* Improved handling of empty or invalid PCAP files before entering rendering loops.

## PCAP handling improvements

* Added safer packet-size validation when reading packets from PCAP files.
* Added bounds checking for packet-position tracking to prevent invalid memory access during large captures.
* Improved timestamp handling for generated PCAP packets.

## Memory and concurrency fixes

* Replaced several unsafe allocation and pointer-handling patterns.
* Fixed multiple race-condition scenarios between networking tasks and UI transitions.
* Improved synchronization around shared RX packet handling.
* Removed excessive debug logging that unnecessarily increased heap usage during runtime.
