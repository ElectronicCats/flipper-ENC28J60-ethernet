# What's Changed in v2.1.0.0

This release significantly expands the Flipper Ethernet application's Passive Discovery capabilities while introducing major stability, memory-management, networking, and lifecycle improvements across the application.

The most visible additions include **CDP and EAPOL passive discovery**, richer **LLDP neighbor information**, **Saved Neighbor History**, persistent Scan Hosts results, and the ability to reuse discovered hosts as targets across multiple networking tools.

This release also improves cancellation, startup reliability, DHCP handling, ENC28J60 lifecycle management, Sniffer and PCAP workflows, and application cleanup.

Starting with **v2.1.0.0**, the application is also built against the **official Flipper Zero firmware SDK**, replacing the previous Unleashed SDK build target.

---

# Passive Discovery Improvements

Passive Discovery has been significantly expanded in this release, evolving from the existing LLDP-based foundation into a unified multi-protocol discovery workflow.

## Expanded LLDP Discovery

LLDP parsing and neighbor details now provide additional network information where available, including:

* VLAN information
* Network policy information
* Device capabilities
* Power over Ethernet information
* Additional protocol metadata

These improvements provide a more complete view of LLDP-capable network infrastructure directly from the Flipper Zero.

---

## CDP Passive Discovery

Added support for **Cisco Discovery Protocol (CDP)** within Passive Discovery.

CDP observations are integrated into the same Passive Discovery workflow used by the existing neighbor database and detail interface.

This allows compatible Cisco network devices to be discovered and inspected without requiring a separate discovery tool.

---

## EAPOL Passive Discovery

Added support for observing **EAPOL traffic** within Passive Discovery.

The application can now display relevant EAP/EAPOL packet metadata and bounded identity information where present.

EAPOL observations use the same unified Passive Discovery database and navigation workflow as LLDP and CDP.

---

## Unified Multi-Protocol Discovery

LLDP, CDP, and EAPOL now share a common Passive Discovery runtime.

The updated architecture provides:

* Shared packet reception
* Unified protocol selection
* Shared neighbor storage
* Consistent neighbor detail views
* Improved protocol-aware neighbor identity handling

The same MAC address can now be preserved as separate observations when discovered through different protocols.

---

# Saved Neighbor History

Added **Saved Neighbor History** for Passive Discovery.

Previously discovered neighbors can now be stored and reviewed without requiring an active discovery session.

Saved Neighbor History includes:

* Offline neighbor browsing
* Protocol filtering
* Neighbor detail views
* History merge behavior
* History clearing

This makes Passive Discovery results more useful across multiple sessions and network inspections.

---

# Scan Hosts Improvements

Scan Hosts now preserves the most recent completed scan result across application restarts.

Saved scan information includes the discovered hosts and a timestamp identifying when the scan was performed.

## Select IP Workflow

Discovered hosts can now be selected directly from Scan Hosts and reused as targets by supported networking tools.

This reduces repeated manual IP entry when moving between host discovery and tools such as:

* Ping
* Ports Scanner
* OS Detector
* Other target-oriented network actions

Cancelled scans are no longer stored as successfully completed scan results.

---

# Improved Cancellation and Responsiveness

Several long-running networking workflows now provide more reliable cancellation and scene transitions.

## Scan Hosts

Scan Hosts cancellation is now cooperative, allowing active scans to stop cleanly when leaving the operation.

## OS Detector

OS Detector now runs asynchronously instead of blocking its scene callback.

This provides:

* Cooperative cancellation
* Improved BACK button behavior
* Clearer completion handling
* Improved failure presentation

These changes reduce UI blocking during longer network operations.

---

# Memory and Startup Reliability

This release includes substantial changes to reduce permanent memory usage and improve behavior when memory is limited.

## Reduced Idle Memory Usage

Large resources are now allocated only while their associated features are active.

Notable changes include:

* The Passive Discovery neighbor database is now scoped to the Passive feature lifecycle.
* The View Packets PCAP index is allocated dynamically only while the packet viewer is active.
* The main application stack has been reduced from 30 KiB to 24 KiB.
* Selected feature-worker stacks have been right-sized for their workloads.

These changes provide more available memory to networking features during normal application use.

## Startup Guards

Memory-sensitive features now perform startup checks before allocating larger resources.

The application can distinguish between:

* Total available heap
* Largest contiguous memory block
* Busy resources
* Allocation failures
* Missing network hardware
* Link failures
* Storage failures
* Receiver registration failures

Affected workflows now provide controlled **Retry**, **Back**, or error states instead of continuing into unsafe allocation paths.

---

# ENC28J60 Reliability Improvements

The ENC28J60 driver received several lifecycle and state-management improvements.

Changes include:

* Controller bank state is now maintained per ENC28J60 instance.
* RX ring state is now maintained per controller instance.
* Controller state is reset during allocation, reset, and startup.
* Partial ENC/SPI/mutex allocation failures now clean up correctly.
* PHY operations now use bounded waits instead of potentially waiting indefinitely.
* Initialization and link failures are propagated to the application.
* DHCP operations preserve and restore the previous receive-filter configuration.

These changes improve reliability when reopening the application or moving repeatedly between networking features.

---

# DHCP and Network Configuration Improvements

DHCP handling has been hardened to improve parsing safety and persistence of acquired network information.

Changes include:

* Improved frame-length validation
* Improved DHCP option-length validation
* Validation of the complete acquired network configuration
* Persistent subnet mask
* Persistent gateway address
* Persistent gateway MAC address
* Improved receive-filter restoration after DHCP operations

The application now avoids restoring DHCP-acquired state when the saved network configuration is incomplete or invalid.

# Application Lifecycle Improvements

Feature-worker ownership and cleanup have been significantly improved.

The application now tracks which feature owns the shared worker thread and prevents unrelated scenes from joining or freeing another feature's worker.

Cleanup has also been improved across:

* BACK navigation
* Scene transitions
* Feature completion
* Application shutdown

Completed workers from features such as Get IP and Sniffer are reclaimed before later operations require their memory.

These changes improve stability during long application sessions involving multiple networking tools.

---

# Sniffer Improvements

Sniffer startup, shutdown, and error handling have been improved.

Changes include:

* Improved worker cleanup
* Controlled handling when storage is unavailable
* Controlled handling when packet reception cannot be registered
* Improved BACK navigation
* Receive-filter restoration when Sniffer stops
* Improved recovery before starting later features

These changes reduce the likelihood of resources remaining allocated after a capture session.

---

# View Packets and PCAP Improvements

PCAP handling has received additional validation and lifecycle improvements.

Changes include:

* Dynamic allocation of the PCAP packet index
* Captured packet length is now used when limiting packet reads
* Improved bounds checking
* Improved navigation and startup behavior
* Controlled handling of empty files
* Controlled handling of invalid files
* Controlled handling of missing or unreadable files

These changes improve both memory usage and stability when browsing packet captures.

---

# Packet and Protocol Safety Improvements

Several networking paths were hardened to reduce unnecessary heap usage and improve packet validation.

Changes include:

* Replaced several temporary TCP, ARP, and checksum heap allocations with bounded local buffers.
* Added additional TCP option bounds validation.
* Added additional OS Detector probe-state validation.
* Improved ARP packet construction.
* Improved ICMP packet handling.
* Improved DHCP packet parsing and construction.

---

# Official Flipper Zero Firmware Compatibility

Starting with **v2.1.0.0**, release builds now target the **official Flipper Zero firmware SDK**.

Previous releases used the Unleashed firmware SDK release channel.

The build configuration now uses:

* `flipperdevices/flipperzero-ufbt-action@v0.1.4`
* uFBT `0.2.6`
* Official Flipper Zero SDK `release` channel

The previous custom Unleashed SDK index is no longer used.

The GitHub Actions build summary also records the SDK/API information used to produce each build.

This change makes the release artifact compatible with the official Flipper Zero firmware build target.
