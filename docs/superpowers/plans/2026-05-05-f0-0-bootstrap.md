## Task 2: License audit of enc28j60 driver (resolve D1)

**Files:**
- Read: `EthernetAppDemo/libraries/chip/enc28j60.c`, `enc28j60.h`, `Spi_lib.c`, `Spi_lib.h`
- Reference (web): EtherShield (jcw/ethershield), EtherCard (njh/EtherCard), Microchip AN833.

**Why:** the current files have no license header. The repo LICENSE is MIT 2025 ElectronicCats. We need to confirm the driver code was not lifted from a GPLv2 source (EtherShield/EtherCard were historically dual-licensed; some forks are GPLv2-only). If GPLv2 contamination exists, options are: (a) attribute and respect GPLv2, (b) reimplement from datasheet.

- [ ] **Step 1: Extract distinctive function signatures from the local driver**

```bash
grep -nE "^(void|uint[0-9]+_t|bool|static)" EthernetAppDemo/libraries/chip/enc28j60.c | head -40
```

Record the top 10 unique function names (e.g. `set_bank`, `read_register_byte`, `write_register_byte`, `enc28j60_start`, `read_buffer`, `write_buffer`, `send_packet`, `receive_packet`).

- [ ] **Step 2: Search upstream EtherShield (jcw) for matching signatures**

```bash
git clone --depth 1 https://github.com/jcw/ethercard /tmp/ethercard
grep -rnE "set_bank|writeReg|enc28j60_start|sendPacket|packetReceive" /tmp/ethercard/
```

Note matches and the LICENSE of `/tmp/ethercard/LICENSE`. EtherCard upstream LICENSE is GPLv2. Compare the matched function bodies side-by-side with the local copies. Decision criteria:
- **Identical or near-identical bodies** → derivative work; either keep GPLv2 (and update repo LICENSE) or reimplement.
- **Same names, different bodies** → naming convention only, no contamination.
- **No matches at all** → original implementation, MIT clean.

Microchip's TCP/IP stack reference code (AN833 / AN1120) is BSD-licensed. If the local driver derives from there instead of EtherCard, license posture is fine.

## Threading model

- **Main app thread** (stack 30 KB, `application.fam:7`): Furi event loop,
  scene callbacks, dispatcher.
- **Ethernet worker thread** (`app_user.c:105`, stack 10 KB): single
  long-lived thread that polls the ENC28J60 RX FIFO and dispatches
  auto-replies (ARP, ICMP). Communicates with scenes via custom events.
- **Per-scene alternative thread** (`app->thread_alternative`):
  scenes that run heavy scans suspend the main worker, allocate a
  temporary thread, run the scan, free the thread, resume worker.
  See `ArpScannerScene.c:196-211`, `ArpspoofingScene.c:13-36`,
  `OsDetector.c:64-70`, `PortsScannerScene.c:131-144`,
  `SnifferScene.c:14-22`.

## Scene registration

X-macro at `scenes_config/app_scene_config.h:6-57`. Each scene
contributes `on_enter`, `on_event`, `on_exit` via macro expansion in
`scenes_config/app_scene_functions.c`.

## RX flow today

1. Worker polls `enc28j60_t.EPKTCNT` (`enc28j60.c:547`).
2. Reads next packet into `enc28j60_t.rx_buffer[1518]` (embedded in
   the chip struct, `enc28j60.h:30-31`).
3. Parses Ethernet header; if ARP/ICMP and matches `is_static_ip || dhcp`,
   replies. Else discards.
4. Scenes that want raw frames suspend the worker and take the radio.

This will be replaced in F0.4 by a single `rx_dispatch` thread with
registrable handler list.

## Protocol craft

`libraries/protocol_tools/` contains pure functions for header build/parse:
- `set_ethernet_header`, `ethernet_get_header`
- `set_ipv4_header`, `ipv4_get_header`
- `set_tcp_header_*`, `tcp_get_header`
- `set_udp_header`, `udp_get_header`
- `arp_set_header`, ARP parse via `ethernet_general`
- `icmp_set_header`
- `dhcp_message_*`

These are the right shape; F1+ extends this directory with `lldp.{c,h}`,
`ipv6.{c,h}`, OT protocols.

## Storage

- PCAP files: `/ext/apps_data/ethernet/files/pcap_DD_MM_YYYY_N.pcap`
  (`SnifferScene.c:70-92`, `app_user.h:48`).
- Settings: **none** — everything resets on app exit. F0.2 introduces
  `settings.cfg`.
