# Passive Discovery Testing

Python tools for generating controlled Ethernet frames to test the **Passive Discovery** functionality of the Flipper Zero Ethernet application.

The project currently supports:

* EAPOL / IEEE 802.1X
* CDP
* LLDP / LLDP-MED

Additional protocol senders can be added following the same testing workflow.

---

# Project Structure

```text
passive-discovery-testing/
├── README.md
├── eapol_test_sender.py
├── cdp_test_sender.py
└── lldp_test_sender.py
```

The only external Python package required is:

```text
Scapy
```

---

# How the Test Works

The PC generates protocol advertisements through its physical Ethernet interface.

The Flipper Zero Ethernet Addon receives these frames while **Passive Discovery** is running.

```text
PC
 │
 │  EAPOL / CDP / LLDP / ...
 │
 ▼
Ethernet
 │
 ▼
Flipper Zero Ethernet Addon
 │
 ▼
Passive Discovery
```

The information displayed by Passive Discovery should correspond to the information generated by the sender script.

Wireshark can optionally be used to verify the transmitted frames independently.

# Linux

The following commands assume Debian/Ubuntu.

## 1. Enter the Project

```bash
cd ~/Downloads/passive-discovery-testing
```

## 2. Create the Virtual Environment

```bash
python3 -m venv .venv
```

If `venv` is not available:

```bash
sudo apt update
sudo apt install python3 python3-venv
```

Then run again:

```bash
python3 -m venv .venv
```

The command normally produces no output when successful.

## 3. Install Scapy

```bash
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install scapy
```

> The virtual environment does not need to be activated. The commands below explicitly use `.venv/bin/python`.

## 4. Find the Ethernet Interface

```bash
ip -br link
```

Example:

```text
lo               UNKNOWN
enp0s31f6        UP
wlp2s0           UP
```

Use the physical Ethernet interface, for example:

```text
enp0s31f6
```

## 5. Run a Sender

### EAPOL

```bash
sudo "$(pwd)/.venv/bin/python" eapol_test_sender.py response-identity \
    -i enp0s31f6 \
    --count 0 \
    --interval 5
```

### CDP

```bash
sudo "$(pwd)/.venv/bin/python" cdp_test_sender.py \
    -i enp0s31f6 \
    --count 0 \
    --interval 5
```

### LLDP / LLDP-MED

```bash
sudo "$(pwd)/.venv/bin/python" lldp_test_sender.py \
    -i enp0s31f6 \
    --count 0 \
    --interval 5
```

Replace `enp0s31f6` with the actual Ethernet interface.

Press `Ctrl+C` to stop transmission.

# Windows

Use **PowerShell** or **Windows Terminal**.

For packet transmission, run the terminal as **Administrator**.

## 1. Enter the Project

```powershell
cd "$HOME\Downloads\passive-discovery-testing"
```

## 2. Create the Virtual Environment

```powershell
python -m venv .venv
```

The command normally returns directly to the PowerShell prompt without displaying a success message. This is expected.

## 3. Install Scapy

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install scapy
```

The virtual environment does not need to be activated.

## 4. Find the Ethernet Interface

Run:

```powershell
.\.venv\Scripts\python.exe -c "from scapy.all import conf; [print('INDEX:', i.index, '| NAME:', i.name, '| NETWORK_NAME:', i.network_name, '| MAC:', i.mac) for i in conf.ifaces.values()]"
```

Look for the physical Ethernet interface.

Example:

```text
INDEX: 14 | NAME: Ethernet | NETWORK_NAME: \Device\NPF_{...} | MAC: d8:5e:d3:29:de:12
```

Use the exact `NAME`:

```text
Ethernet
```

> Do not use the numeric index (`14`) as the `-i` argument.

For the example above, use:

```text
-i "Ethernet"
```

## 5. Run a Sender

### EAPOL

```powershell
.\.venv\Scripts\python.exe eapol_test_sender.py response-identity `
    -i "Ethernet" `
    --count 0 `
    --interval 5
```

### CDP

```powershell
.\.venv\Scripts\python.exe cdp_test_sender.py `
    -i "Ethernet" `
    --count 0 `
    --interval 5
```

### LLDP / LLDP-MED

```powershell
.\.venv\Scripts\python.exe lldp_test_sender.py `
    -i "Ethernet" `
    --count 0 `
    --interval 5
```

Replace `"Ethernet"` with the actual interface `NAME` reported by Scapy.

Press `Ctrl+C` to stop transmission.

# Expected Sender Output

When a sender starts successfully, it displays the information being placed in the generated frames.

For example, LLDP may display:

```text
[ Ethernet ]
Interface              : Ethernet
SOURCE MAC             : d8:5e:d3:29:de:12

[ Mandatory LLDP ]
CHASSIS ID             : d8:5e:d3:29:de:12
PORT MAC / Port ID     : d8:5e:d3:29:de:12
TTL                    : 120 seconds

[ System Information ]
SYSTEM NAME            : LAB-SWITCH-01
MANAGEMENT IPV4        : 192.0.2.10

[ IEEE 802.1 VLAN ]
PORT VLAN ID           : 1
VLAN NAME              : LAB-VLAN
```

Once transmission starts, messages such as the following should appear:

```text
Starting LLDP transmission. Press Ctrl+C to stop.
[TX #1] LLDP ...
[TX #2] LLDP ...
```

`--count 0` means continuous transmission.

`--interval 5` means one transmission every 5 seconds.

# Testing with Flipper Zero Passive Discovery

Connect the computer's physical Ethernet interface to the Ethernet Addon used by the Flipper Zero.

Start one of the sender scripts and leave it running.

Then:

```text
1. Start the protocol sender on the PC
          ↓
2. Open the Ethernet application on Flipper Zero
          ↓
3. Start Passive Discovery
          ↓
4. Wait for the generated protocol to be detected
          ↓
5. Open the discovered device/protocol information
          ↓
6. Compare it with the values printed by the sender
```

For example, if the LLDP sender reports:

```text
SYSTEM NAME       : LAB-SWITCH-01
MANAGEMENT IPV4   : 192.0.2.10
PORT VLAN ID      : 1
VLAN NAME         : LAB-VLAN
```

Passive Discovery should report the corresponding LLDP information.

The same principle applies to EAPOL, CDP, and future supported protocols:

```text
Sender output
      ↕
Passive Discovery output
```

The test passes when Passive Discovery detects the generated protocol and correctly displays the expected information.

# Optional Wireshark Validation

Wireshark can be used between the sender and Passive Discovery tests to independently verify the generated frames.

Capture traffic on the same physical Ethernet interface.

Current display filters:

```text
Protocol    Wireshark Filter
--------    ----------------
EAPOL       eapol
CDP         cdp
LLDP        lldp
```

The expected workflow is:

```text
Sender
   ↓
Wireshark
   ↓
Passive Discovery
```

Compare the values at each stage:

```text
Sender output
     =
Wireshark decoded frame
     =
Passive Discovery output
```

If all three match, both the generated test frame and Passive Discovery parsing can be validated.

Wireshark is optional when only a quick Passive Discovery functional test is required.

# Adding Future Protocols

Future protocol senders should follow the same convention:

```text
<protocol>_test_sender.py
```

For example:

```text
newprotocol_test_sender.py
```

Each sender should:

1. Accept the Ethernet interface as an argument.
2. Display the important information being generated.
3. Support repeated transmission.
4. Allow the generated information to be compared with Passive Discovery.
5. Stop cleanly with `Ctrl+C`.

The general testing workflow should remain unchanged:

```text
Configure Sender
      ↓
Transmit Frames
      ↓
Passive Discovery
      ↓
Compare Results
```
